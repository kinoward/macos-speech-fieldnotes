# 实验记录与复用指南

[实践笔记](../../README.zh-CN.md) · [English](../en/experiments.md)

先决定自己要测什么。**文件吞吐**是已有录音多久转换为文本。**实时草稿延迟**是听众多久能看到第一段可读文字。**定稿时间**是某一段何时不再变化。即使文件识别速度相同，听众实际等待的时间也可能很不一样。

## 复现测量

先完成[对应 Demo 的准备](../../README.zh-CN.md#运行任一-demo)。脚本会在本机生成全新的中性普通话音频。`VOICE` 可选择已安装的普通话 `say` 音色，参考测试使用 Tingting。系统音色生成的素材供本机个人测试。

```bash
mkdir -p scratch
./scripts/make-sample scratch/measure.mp4
python3 experiments/time-file.py scratch/measure.mp4
./experiments/make-probes scratch/probes
node --test experiments/revisions.test.mjs
```

在另一终端启动 `OPEN_BROWSER=0 ./demos/live-translation/run`，再执行：

```bash
(
  for case_name in negation condition noun independent mixed-condition pronoun-condition quiet noise silence; do
    node demos/live-translation/replay.mjs "scratch/probes/$case_name.wav" --expect "$case_name" --text || exit 1
  done
)
```

在视频 Demo 的 Python 虚拟环境中，下面的命令会复查竖屏两行排版、AAC 中途的时间缺口，并确认故意推迟的音轨能被检出。

```bash
python3 experiments/video-regressions.py
```

文件计时器只提取一次 WAV，随后三次启动已编译的 Swift 程序。计时包含进程启动、识别和读回 JSON；编译与模型安装位于测量之前。耗时除以音频时长得到实时系数，数值越小越快。[文件计时器](../../experiments/time-file.py)

回放边解码边发送，按照样本时钟每 90 毫秒发送一包。`readyMs` 从建立连接开始计算，`firstMs` 与 `doneMs` 从桥接层发回 `ready` 开始计算。后续音频仍在播放时，第一段有可能已经定稿。`doneMs − audioMs` 是送完最后一包后的收尾耗时。`--text` 会输出文字，便于核对句意；`--expect` 按样例名称检查预期结果。例如，两条独立分句必须得到两个小节，即使中英文同时误合为一节也会报错。回放自己的录音时可省略 `--expect`。[回放客户端](../../demos/live-translation/replay.mjs)

## 首次发布时的实测结果

参考设备为 Apple M4、macOS 27.3、SDK 27.2、Swift 6.4.2、Node 26.13.1、FFmpeg 9.0.2。干净目录中的视频环境使用 Python 3.9.6 和 Pillow 11.3。语言资源在测量前已安装。下表每行均为**一次按真实时钟回放**，实时服务与 Swift 子进程的 IP 连接仅允许本机回环地址。

首次发布的回放工具会在连接前解码完整录音；当前版本收到 `ready` 后才启动 FFmpeg，因此首条草稿计时也包含解码器启动时间。

| 样例 | 音频（毫秒） | 首条中文草稿（毫秒） | 首条英文草稿（毫秒） | 首条英文定稿（毫秒） | 最终表现 |
| --- | ---: | ---: | ---: | ---: | --- |
| 否定句，插入 700 毫秒停顿 | 3,543 | 1,026 | 1,091 | 3,676 | 保留为一个小节，英文包含“没有说要关灯”的否定关系。 |
| 条件从句 | 4,288 | 1,000 | 2,086 | 4,343 | 条件和结果保持在一起。 |
| 名词短语 | 3,893 | 1,027 | 2,064 | 3,976 | 修饰成分和中心词保留在同一小节。 |
| 两个独立分句 | 3,891 | 1,026 | 2,078 | 4,006 | 一个定稿分段中得到两个独立翻译的小节。 |
| 条件句降低 24 dB | 4,288 | 1,008 | 2,063 | 4,343 | 条件关系保持完整。 |
| 条件句加入固定种子的粉红噪声 | 4,288 | 1,022 | 2,044 | 4,325 | 最终句意与干净样本一致。 |
| 数字静音 | 3,000 | — | — | — | 零条字幕事件，会话正常结束。 |

独立分句样例最初只得到一个英文句子。Speech 最终结果中有一个“空格＋逗号”的带时间片段，原判断把它当作普通文字，将候选断点放在标点之前。修正时只在**判断片段是否属于标点**时去除空白，保留原字符偏移。两句随后分开翻译，否定句和条件句对照仍保持完整。[断句实现](../../demos/live-translation/SpeechBridge.swift) · [样例文稿及停顿](../../experiments/make-probes)

文件样例含 **5.933 秒**天文主题语音。一次实验的三个新进程分别耗时 **0.192、0.187、0.188 秒**，FFmpeg 提取音轨耗时 **0.027 秒**。初稿将“望远镜”写成“望远近”，视频专题给出了校对后的字幕。系统语言资源更新后，识别与翻译结果可能变化。[视频流程](video-captions.md)

## 历史实验

| 实验 | 观察结果 | 可复用的经验 |
| --- | --- | --- |
| 一段 52.33 秒的单人录音 | 三轮 ASR 获得最终文本分别耗时 **1.05、0.82、0.80 秒**；历史案例的两遍 H.265 编码约用 12 分钟。 | 记录每项计时的起止位置。历史数据只测 ASR，公开脚本还计入 Swift 进程启动与读回结果的时间。 |
| 早期实时原型，19.12 秒合成普通话 | 三次首条英文分别为 **5.11、2.06、2.05 秒**，首段定稿约 **16.5 秒**。后续断句实验在其受控样本上约 **1.1 秒**显示首条英文。 | 分别记录草稿和定稿的时间，并注明输入与预热情况。 |
| 专有词提示 | 小规模干净和加噪同音词对照中，默认 SpeechTranscriber 加提示后未观察到改善。DictationTranscriber 加提示后，在干净语音中修正两个目标词，在轻噪声中修正一个。 | 保留默认识别器作为基线，切换前用**同一**说话人、文稿和负对照比较。[Apple DictationTranscriber](https://developer.apple.com/documentation/speech/dictationtranscriber) |

## 验收记录

- 从 Git 暂存文件导出干净目录，重编两个 Swift 入口，安装锁文件中的 Node 依赖并创建新的 Python 环境。运行所需的程序、包和字体均可从项目说明指定的来源获取。
- 视频 Demo 自动生成可编辑时间轴，并可从原片重新烧录校对后的字幕。检查脚本逐帧比对恒定和可变帧率的显示时间，按数据包哈希核对复制的 48 kHz AAC。0.80 MB 紧预算的校对版成片为 **769,898 字节**，178 帧的显示时间全部一致。合成 4:3 样例输出 2688 × 2016、60000/1001 fps、Main 10；字幕仅在设定时段出现在画面上。[媒体检查脚本](../../experiments/check-media.py)
- Chrome 模拟麦克风覆盖真实 AudioWorklet、WebSocket、Swift 和网页 DOM。点击停止及触发输入音轨结束，两种操作均得到版本匹配的中英定稿，释放输入，网页保留字幕。另用确定性测试让旧译文在中文修订后抵达。[版本回归测试](../../experiments/revisions.test.mjs)
- 语言包已就绪时，文件识别在禁止出站 IP 连接的进程策略下运行。实时服务和子进程仅获准连接回环地址，外部地址的连接对照被拒绝。该试验验证应用进程的网络边界；主机网络和独立的 Apple 系统守护进程没有被整体隔离。实体麦克风声学表现、长时间多人对话仍待验证。

## 可以继续研究什么

| 问题 | 建议的对照 | 观测指标 |
| --- | --- | --- |
| 术语提示能改善真人领域词吗？ | 同一份获同意的本地录音，对照默认模块与 DictationTranscriber，分别启用和关闭提示，加入发音接近但本来正确的词。 | 目标词错误、错误替换、首条草稿延迟。 |
| 断句策略能适应其他房间吗？ | 先固定距离播放相同句子，再分别改变声音强度、背景噪声和麦克风距离。 | 丢词、误切、漏切、讲话结束至定稿的延迟。 |
| 长谈话会出现什么变化？ | 固定单人语音，然后加入轮流发言和重叠语音，均按真实时间回放。 | 未配对定稿、队列峰值、内存和延迟随时间的变化。 |
| 实时路径怎样兼容 macOS 26？ | 只替换音频转换器，在真实 macOS 26 上输入相同 PCM 对照。 | 最后一块样本、音频时间范围、草稿与定稿行为。 |

新增实验可按“问题、系统与语言包状态、输入来源、控制变量、计时起点、观察结果、局限”记录。公开部分使用汇总指标与已获许可的中性文字，私人录音和转写文本由其所有者留存。
